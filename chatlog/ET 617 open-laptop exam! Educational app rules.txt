Here's the setup, start to finish. VS Code has Git support built in, but it needs Git installed on your laptop.

1. Install Git

Download from git-scm.com and install with the defaults (Windows/macOS/Linux all supported).

Check it worked: open a terminal and run git --version.

2. Tell Git who you are (one time)

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Use the same email that's on your GitHub account so commits are linked to you.

3. Open your project in VS Code

File > Open Folder and pick your project folder.

Click the Source Control icon in the left sidebar (the branch-shaped icon, or press Ctrl+Shift+G).

Click Initialize Repository. VS Code now tracks changes in that folder.

4. Sign in to GitHub from VS Code

Click the Accounts icon (bottom-left, person silhouette) > Sign in with GitHub.

A browser window opens; authorize VS Code, then return to the editor.

This handles authentication, so you won't need to type passwords or set up SSH keys.

5. Connect to a GitHub repository

Easiest: create an empty repo on github.com first, then copy its URL.

In VS Code, open the terminal (`Ctrl+``) and run:

git remote add origin https://github.com/yourusername/your-repo.git
git branch -M main

Alternatively, once your repo is initialized, use Publish to GitHub in the Source Control panel, which creates the repo and links it in one step.

6. The daily workflow

Edit files. Changed files appear in the Source Control panel.

Click + next to a file (or on "Changes") to stage it.

Type a message in the box and click Commit.

Click Sync Changes or Push to upload to GitHub.

Quick troubleshooting

"Git not found": restart VS Code after installing Git, or check that Git is on your PATH.

Push asks for credentials repeatedly: sign out and back in through the Accounts menu.

Wrong author on commits: re-run the two git config commands above.

For your exam: do a full test run today. Create a dummy repo, make a small change, commit, push, and confirm it appears on GitHub. During the exam, commit and push frequently with meaningful messages, since your version history is part of the integrity check.

It's faster, but speed doesn't matter for a project this small.

Linting earns no marks. The rubric covers design fit, pedagogy, and your AI judgement.
